# Step 5: PostToolUse Hooks (Auto-Validators)

> **Generated by `framework/generate.sh`:** All hook scripts (`validators/`, `check-env.sh`, `audit-docs-hook.sh`, `audit-docs.sh`) are generated by running the generator in Step 1.5. This document describes the hook architecture and what the scripts contain, for reference and customization.

> **Feature gate:** Only create validator hooks if `{{discovery.features.post_tool_use_hooks}}` is true. `check-env.sh` is always created (advisory only — it never blocks). `audit-docs-hook.sh` and `audit-docs.sh` are only created when `features.audit_docs` is true.

## Prerequisites

- Discovery context from Step 1
- Agent definitions from Step 4 (hooks are wired in builder agent frontmatter)

## Overview

Hooks run automatically after every `Write` or `Edit` tool call made by the builder agent. They validate the file that was just written and return a JSON decision:

- `{}` — allow (no issues found)
- `{"decision": "block", "reason": "..."}` — force the agent to fix before continuing

Hook wiring happens in the builder agent's frontmatter (see Step 4), not in a global config. This means only the builder agent gets validation hooks — the validator agent and the main session do not.

All hook scripts are **bash** and use `jq` for JSON I/O. They read JSON from stdin and emit JSON to stdout.

### Hook I/O Contract

**Input** (stdin): A JSON object provided by the platform containing:

```json
{
  "tool_name": "Write",              // Name of the tool that was called
  "tool_input": {
    "file_path": "/absolute/path/to/file.ts",  // For Write/Edit: path to the affected file
    "command": "git commit -m '...'"            // For Bash: the command that was executed
  }
}
```

- `tool_input.file_path` — present for `Write` and `Edit` tool calls. Absolute path to the file that was created or modified.
- `tool_input.command` — present for `Bash` tool calls. The shell command that was executed.
- Other fields may be present depending on the platform; hooks should access only the fields they need and use `jq`'s `// ""` fallback for optional fields.

**Output** (stdout): A JSON object with exactly one of these shapes:

| Output | Meaning | Agent behavior |
|--------|---------|----------------|
| `{}` | Validation passed | Agent continues normally |
| `{"decision": "block", "reason": "..."}` | Validation failed | Agent must fix the issue before continuing |
| `{"reason": "..."}` | Advisory (no block) | Message surfaces to agent but does not block |

Hooks must always produce valid JSON on stdout, even on internal errors. If a hook cannot run (e.g., linter not found), emit `{}` to avoid blocking the agent for infrastructure issues.

## Files to Create

```
{{discovery.agent_dir}}/hooks/
├── validators/
│   ├── {{linter_name}}_validator.sh    # One per entry in discovery.linters
│   └── {{type_checker}}_validator.sh   # One per entry in discovery.type_checkers
├── check-env.sh                        # Session-start environment check
├── audit-docs-hook.sh                  # Post-commit doc staleness warning
└── audit-docs.sh                       # Full audit script — JSON output for /audit-docs
```

Create one validator script per entry in `{{discovery.linters}}` and one per entry in `{{discovery.type_checkers}}`. Convert the tool name to lowercase for the filename: `ESLint` → `eslint_validator.sh`, `Ruff` → `ruff_validator.sh`, `tsc` → `tsc_validator.sh`.

> **Filename casing:** The `{{name}}` in both the filename (`{{name}}_validator.sh`) and the builder frontmatter hook command must be lowercased consistently. A mismatch (e.g., `ESLint_validator.sh` in the filename but `eslint_validator.sh` in the frontmatter) will cause the hook to silently fail with a "file not found" error. Always lowercase both.

> **File permissions:** After creating each `.sh` script, ensure it has execute permissions (`chmod +x`). Without `+x`, the `bash` invocation in the builder frontmatter will work (since `bash script.sh` doesn't require `+x`), but direct invocation patterns and some platform integrations may fail silently.

## Validator Template

All validators follow the same pattern. Adapt the command, file extension guard, and working directory for each linter/type-checker.

**Path derivation:** Use `git rev-parse --show-toplevel` as the primary method to derive `PROJECT_DIR`. This eliminates manual depth counting and works regardless of where the agent directory is nested. Falls back to `SCRIPT_DIR` depth for non-git environments.

> **Pseudo-template syntax in bash blocks:** The `{{#if}}`, `{{#each}}`, and `{{field}}` markers inside the bash code block below are instructions for the setup agent — they are not literal bash syntax. The setup agent resolves these when generating the actual `.sh` file. The final output is plain bash with no template markers.

> **Trust boundary:** The `{{linter.cmd}}` value comes from discovery (Step 1), which reads project manifest files (package.json, pyproject.toml, etc.). Discovery should validate that detected commands match expected patterns (e.g., starts with a known binary name like `eslint`, `ruff`, `tsc`). Do not render arbitrary strings from project files into the command position of these scripts.

```bash
#!/usr/bin/env bash
# Validator: {{linter_name}}
# Runs {{linter.cmd}} on files matching {{linter.file_extensions}}

set -euo pipefail

# Error handling strategy: set -euo pipefail catches bugs in the script itself.
# If the script fails before producing output (e.g., jq not found), the platform
# sees a non-zero exit with no JSON — behavior varies by platform. To prevent
# blocking the agent on infrastructure issues, wrap critical sections in explicit
# error handling below.

SCRIPT_DIR="$(cd "$(dirname "$0")" && pwd)"
PROJECT_DIR="$(git rev-parse --show-toplevel 2>/dev/null || { cd "$SCRIPT_DIR/../../.." && pwd; })"
{{#if discovery.workspaces}}
# Monorepo: determine workspace from file path
match_workspace() {
  local fp="$1"
  local rel="${fp#"$PROJECT_DIR/"}"
{{#each discovery.workspaces}}
  [[ "$rel" == "{{path}}"* ]] && { echo "$PROJECT_DIR/{{path}}"; return; }
{{/each}}
  echo "$PROJECT_DIR"
}
{{else}}
TARGET_DIR="$PROJECT_DIR/{{discovery.directories.backend_root or ''}}"
# NOTE: Adapt the directory above per validator. Backend linters use backend_root,
# frontend linters use frontend_root, root-scoped tools use '' (project root).
{{/if}}
LOG_FILE="$SCRIPT_DIR/{{linter_name}}_validator.log"

# Portable timeout: macOS does not ship GNU `timeout`.
# Falls back to a background-process-based timeout on macOS.
if command -v timeout > /dev/null 2>&1; then
  run_with_timeout() { timeout "$@"; }
else
  run_with_timeout() {
    local secs="$1"; shift
    "$@" &
    local pid=$!
    ( sleep "$secs" && kill "$pid" 2>/dev/null ) &
    local watchdog=$!
    wait "$pid" 2>/dev/null
    local rc=$?
    kill "$watchdog" 2>/dev/null || true; wait "$watchdog" 2>/dev/null || true
    return $rc
  }
fi

log() {
  # Sanitize output: redact long quoted strings that may contain secrets
  local msg="$2"
  msg="$(echo "$msg" | sed -E 's/"[^"]{20,}"/[REDACTED]/g' | sed -E "s/'[^']{20,}'/[REDACTED]/g")"
  echo "$(date '+%Y-%m-%dT%H:%M:%S') $1: $msg" >> "$LOG_FILE"
}

# Read hook input from stdin (with size limit to prevent memory exhaustion)
input="$(head -c 65536)"
file_path="$(echo "$input" | jq -r '.tool_input.file_path // ""' 2>/dev/null)" || {
  echo '{}'; exit 0
}

# Guard: only run for relevant file extensions
# Adapt this case pattern to match {{linter.file_extensions}}
case "$file_path" in
  *.py) ;;                          # Python: *.py
  # *.ts|*.tsx|*.js|*.jsx) ;;      # JS/TS
  # *.rb) ;;                        # Ruby
  # *.ex|*.exs) ;;                  # Elixir
  *) echo '{}'; exit 0 ;;
esac

{{#if discovery.workspaces}}
# Resolve workspace directory for this file
TARGET_DIR="$(match_workspace "$file_path")"
{{/if}}

log "INFO" "Validating: $file_path"

# Run the linter/type-checker
# Adapt command from {{linter.cmd}}
output=""
# Timeout in seconds — single-file lints typically complete in seconds;
# whole-project type checkers (e.g. tsc --noEmit) may need the full 120s.
# Adjust per tool if needed.
if output=$(cd "$TARGET_DIR" && run_with_timeout 120 {{linter.cmd}} -- "$file_path" 2>&1); then
  log "INFO" "PASS: $file_path"
  echo '{}'
else
  # Truncate output to 500 chars
  output="${output:0:500}"
  log "WARN" "FAIL: $file_path -- $output"
  jq -n --arg reason "{{linter_name}} failed:
$output" '{"decision": "block", "reason": $reason}'
fi
```

> **Log hygiene:** Validator log files (`*_validator.log`) should be added to `.gitignore` to prevent accidental commits. Linter output can include source code lines that may contain sensitive values.

## `check-env.sh` — Session-Start Environment Check

Wired as a session-start hook (or `PreToolUse` on the first tool call). Checks for the presence of environment files and prints a single status line. It never blocks, never creates files, never fills in values.

```bash
#!/usr/bin/env bash
set -euo pipefail

# Read hook input from stdin (may be empty)
cat > /dev/null

SCRIPT_DIR="$(cd "$(dirname "$0")" && pwd)"
PROJECT_DIR="$(git rev-parse --show-toplevel 2>/dev/null || { cd "$SCRIPT_DIR/../.." && pwd; })"

# Adapt from {{discovery.env_files.found}} and common conventions
ENV_CANDIDATES=(".env" ".env.local" ".env.development")

for f in "${ENV_CANDIDATES[@]}"; do
  if [[ -f "$PROJECT_DIR/$f" ]]; then
    jq -n --arg reason "$(printf '\xe2\x9c\x93 %s found' "$f")" \
      '{reason: $reason}'
    exit 0
  fi
done

hint=""
[[ -f "$PROJECT_DIR/.env.example" ]] && hint=" (copy from .env.example)"
candidates_str="$(printf '%s, ' "${ENV_CANDIDATES[@]}" | sed 's/, $//')"
jq -n --arg reason "$(printf '\xe2\x9a\xa0 No environment file found%s. The app may not start correctly. Looked for: %s' "$hint" "$candidates_str")" \
  '{reason: $reason}'
```

The output surfaces in the agent's context at session start, so it's visible without being disruptive. Adapt `ENV_CANDIDATES` to match `{{discovery.env_files}}`.

## `audit-docs-hook.sh` — Post-Commit Doc Staleness Warning

Wired as a `PostToolUse` hook that matches Bash tool calls containing `git commit`. Runs a fast filename-pattern scan of `docs/` — no git log queries, no file reads — and prints a warning if any high-risk temporary files are present. Advisory only; never blocks the commit.

```bash
#!/usr/bin/env bash
set -euo pipefail

# Read hook input from stdin (size-limited for safety)
input="$(head -c 65536)"
command="$(echo "$input" | jq -r '.tool_input.command // ""' 2>/dev/null)" || {
  echo '{}'; exit 0
}

# Only run on git commit
[[ "$command" == *"git commit"* ]] || { echo '{}'; exit 0; }

SCRIPT_DIR="$(cd "$(dirname "$0")" && pwd)"
PROJECT_DIR="$(git rev-parse --show-toplevel 2>/dev/null || { cd "$SCRIPT_DIR/../.." && pwd; })"
DOCS_DIR="$PROJECT_DIR/docs"

[[ -d "$DOCS_DIR" ]] || { echo '{}'; exit 0; }

# Filename patterns indicating temporary docs
TEMP_PATTERN='_(SUMMARY|ANALYSIS|RESULTS?|CHECKLIST|MEETING|NOTES?|v[0-9]+|[0-9]{4}-[0-9]{2}-[0-9]{2}).*\.md$'

flagged=()
while IFS= read -r f; do
  name="$(basename "$f")"
  if echo "$name" | grep -qEi "$TEMP_PATTERN"; then
    # Compute path relative to project root
    flagged+=("${f#"$PROJECT_DIR/"}")
  fi
done < <(find "$DOCS_DIR" -name "*.md" -type f 2>/dev/null)

if (( ${#flagged[@]} > 0 )); then
  file_list="$(printf '  - %s\n' "${flagged[@]}")"
  jq -n --arg reason "$(printf '\xe2\x9a\xa0 Temporary docs detected in docs/:\n%s\nConsider running /audit-docs to clean these up.' "$file_list")" \
    '{reason: $reason}'
else
  echo '{}'
fi
```

This is deliberately shallow — it only looks at filenames, not content or git history. The full staleness analysis (co-change, content signals) is left to the `/audit-docs` command via `audit-docs.sh`.

## `audit-docs.sh` — Full Audit Script

Standalone script that collects all deterministic signals for the `/audit-docs` command. Outputs structured JSON to stdout. The `/audit-docs` command invokes this script once and interprets the results — see Step 3 for the command definition.

**Requires:** bash 3.2+, `jq`, `git`.

```bash
#!/usr/bin/env bash
# audit-docs.sh — Collect documentation health signals as JSON
# Requires: bash 3.2+, jq, git

set -euo pipefail

# --- Defaults ---
DOCS_DIR="docs"
SPECS_DIR="specs"
INDEX_FILE="docs/README.md"
DAYS_HIGH=90
DAYS_MEDIUM=60
SPECS_MAX_AGE=30

# --- Argument parsing ---
while [[ $# -gt 0 ]]; do
  case "$1" in
    --docs-dir)    DOCS_DIR="$2"; shift 2 ;;
    --specs-dir)   SPECS_DIR="$2"; shift 2 ;;
    --index-file)  INDEX_FILE="$2"; shift 2 ;;
    --days-high)   DAYS_HIGH="$2"; shift 2 ;;
    --days-medium) DAYS_MEDIUM="$2"; shift 2 ;;
    --specs-max-age) SPECS_MAX_AGE="$2"; shift 2 ;;
    *) echo "Unknown option: $1" >&2; exit 1 ;;
  esac
done

# --- Dependency check ---
for cmd in jq git; do
  command -v "$cmd" > /dev/null 2>&1 || {
    echo "ERROR: $cmd is required but not found." >&2
    [[ "$cmd" == "jq" ]] && echo "Install: brew install jq (macOS) or apt-get install jq (Linux)" >&2
    exit 1
  }
done

NOW="$(date +%s)"
GENERATED_AT="$(date -u '+%Y-%m-%dT%H:%M:%SZ')"

# Temp pattern for detecting temporary docs (matches audit-docs-hook.sh)
TEMP_PATTERN='_(SUMMARY|ANALYSIS|RESULTS?|CHECKLIST|MEETING|NOTES?|v[0-9]+|[0-9]{4}-[0-9]{2}-[0-9]{2}).*\.md$'

# Version/date reference pattern for content scanning
STALE_VERSION_PATTERN='(v[0-9]+\.[0-9]+\.[0-9]+|20[0-9]{2}-(0[1-9]|1[0-2])-(0[1-9]|[12][0-9]|3[01])|Q[1-4] 20[0-9]{2}|Sprint [0-9]+)'

# --- Helper: read index file into a string for grep ---
INDEX_CONTENT=""
[[ -f "$INDEX_FILE" ]] && INDEX_CONTENT="$(cat "$INDEX_FILE")"

# ================================================================
# AUDIT DOC FILES
# ================================================================

audit_doc_file() {
  local file="$1"
  local basename_file
  basename_file="$(basename "$file")"

  # Last edit: epoch and days ago
  local last_edit_epoch
  last_edit_epoch="$(git log -1 --format=%at -- "$file" 2>/dev/null || echo 0)"
  local last_edit_days=0
  local last_edit_date="unknown"
  if (( last_edit_epoch > 0 )); then
    last_edit_days=$(( (NOW - last_edit_epoch) / 86400 ))
    last_edit_date="$(date -r "$last_edit_epoch" '+%Y-%m-%d' 2>/dev/null || date -d "@$last_edit_epoch" '+%Y-%m-%d' 2>/dev/null || echo 'unknown')"
  fi

  # Commit count in lookback window
  local commits_90d
  commits_90d="$(git log --since="${DAYS_HIGH} days ago" --oneline -- "$file" 2>/dev/null | wc -l | tr -d ' ')"

  # Temporary file detection
  local is_temporary=false
  local temp_pattern_matched="null"
  if echo "$basename_file" | grep -qEi "$TEMP_PATTERN"; then
    is_temporary=true
    temp_pattern_matched="$(echo "$basename_file" | grep -oEi '_(SUMMARY|ANALYSIS|RESULTS?|CHECKLIST|MEETING|NOTES?|v[0-9]+|[0-9]{4}-[0-9]{2}-[0-9]{2})' | head -1)"
  fi

  # Index check
  local in_index=false
  if [[ -n "$INDEX_CONTENT" ]] && echo "$INDEX_CONTENT" | grep -qF "$basename_file"; then
    in_index=true
  fi

  # Co-change analysis: files changed most since this doc was last edited
  # NOTE: This runs `git log` per doc file, which is O(docs x commits).
  # For large repos (5000+ commits, 30+ docs), consider optimizing by running
  # `git log --since="90 days ago" --name-only` once and building a lookup map,
  # then filtering per doc by its last-edit date. This reduces to O(commits) + O(docs x changed-files).
  local co_change_json="[]"
  if (( last_edit_epoch > 0 )); then
    local last_doc_commit
    last_doc_commit="$(git log -1 --format=%H -- "$file" 2>/dev/null || echo '')"
    if [[ -n "$last_doc_commit" ]]; then
      co_change_json="$(
        git log "$last_doc_commit"..HEAD --name-only --pretty=format: 2>/dev/null \
        | grep -v '^\s*$' \
        | grep -v '\.md$' \
        | sort | uniq -c | sort -rn | head -10 \
        | while read -r count path; do
            [[ -n "$path" ]] && jq -n --arg p "$path" --argjson c "$count" '{path: $p, commits_since_doc_edit: $c}'
          done \
        | jq -s '.'
      )"
      [[ -z "$co_change_json" || "$co_change_json" == "null" ]] && co_change_json="[]"
    fi
  fi

  # TODO count
  local todo_count
  todo_count="$(grep -ciE '\bTODO\b' "$file" 2>/dev/null || echo 0)"

  # Stale version/date references
  local has_stale_versions=false
  if grep -qE "$STALE_VERSION_PATTERN" "$file" 2>/dev/null; then
    has_stale_versions=true
  fi

  # Risk level assignment
  local risk_level="low"
  if [[ "$is_temporary" == "true" ]] || { (( last_edit_days > DAYS_HIGH )) && (( commits_90d == 0 )); }; then
    risk_level="high"
  elif (( last_edit_days > DAYS_MEDIUM )) || [[ "$in_index" == "false" ]] || (( todo_count > 0 )); then
    risk_level="medium"
  fi

  # Emit JSON object
  jq -n \
    --arg path "$file" \
    --argjson last_edit_days "$last_edit_days" \
    --arg last_edit_date "$last_edit_date" \
    --argjson commits_90d "$commits_90d" \
    --argjson is_temporary "$is_temporary" \
    --arg temp_pattern_matched "$temp_pattern_matched" \
    --argjson in_index "$in_index" \
    --argjson co_change_files "$co_change_json" \
    --argjson todo_count "$todo_count" \
    --argjson has_stale_versions "$has_stale_versions" \
    --arg risk_level "$risk_level" \
    '{
      path: $path,
      last_edit_days: $last_edit_days,
      last_edit_date: $last_edit_date,
      commits_90d: $commits_90d,
      is_temporary: $is_temporary,
      temp_pattern_matched: (if $temp_pattern_matched == "null" then null else $temp_pattern_matched end),
      in_index: $in_index,
      co_change_files: $co_change_files,
      todo_count: $todo_count,
      has_stale_versions: $has_stale_versions,
      risk_level: $risk_level
    }'
}

# ================================================================
# AUDIT SPEC FILES
# ================================================================

audit_spec_file() {
  local file="$1"
  local basename_file
  basename_file="$(basename "$file")"

  # Age in days
  local created_epoch
  created_epoch="$(git log --follow --diff-filter=A --format=%at -- "$file" 2>/dev/null | tail -1)"
  [[ -z "$created_epoch" ]] && created_epoch="$(git log -1 --format=%at -- "$file" 2>/dev/null || echo "$NOW")"
  local age_days=$(( (NOW - created_epoch) / 86400 ))

  # Git evidence: commits mentioning this spec's name
  local spec_name="${basename_file%.md}"
  local git_evidence_commits
  git_evidence_commits="$(git log --all --oneline --fixed-strings --grep="$spec_name" 2>/dev/null | wc -l | tr -d ' ')"

  # Check if files listed in the spec's "New Files" or "Relevant Files" exist
  local listed_files_exist=false
  if [[ -f "$file" ]]; then
    # Extract file paths mentioned after "New Files" or "Relevant Files" headers
    local listed_paths
    listed_paths="$(grep -E '^\s*[-*]\s+`[^`]+`' "$file" 2>/dev/null | grep -oE '`[^`]+\.[a-z]+`' | tr -d '`' || true)"
    if [[ -n "$listed_paths" ]]; then
      local all_exist=true
      while IFS= read -r p; do
        [[ -f "$p" ]] || { all_exist=false; break; }
      done <<< "$listed_paths"
      [[ "$all_exist" == "true" ]] && listed_files_exist=true
    fi
  fi

  # Classification
  local classification="never_built_recent"
  if (( git_evidence_commits > 0 )) && [[ "$listed_files_exist" == "true" ]]; then
    classification="built_complete"
  elif (( git_evidence_commits > 0 )); then
    classification="built_partial"
  elif (( age_days > SPECS_MAX_AGE )); then
    classification="never_built_old"
  fi

  jq -n \
    --arg path "$file" \
    --argjson age_days "$age_days" \
    --argjson git_evidence_commits "$git_evidence_commits" \
    --argjson listed_files_exist "$listed_files_exist" \
    --arg classification "$classification" \
    '{
      path: $path,
      age_days: $age_days,
      git_evidence_commits: $git_evidence_commits,
      listed_files_exist: $listed_files_exist,
      classification: $classification
    }'
}

# ================================================================
# MAIN: Collect all signals
# ================================================================

# Collect doc files
doc_files=()
if [[ -d "$DOCS_DIR" ]]; then
  while IFS= read -r f; do
    doc_files+=("$f")
  done < <(find "$DOCS_DIR" -name "*.md" -type f 2>/dev/null | sort)
fi
# Also audit root-level doc files
for root_doc in CHANGELOG.md README.md; do
  [[ -f "$root_doc" ]] && doc_files+=("$root_doc")
done

# Collect doc entries as JSONL (one JSON object per line)
doc_entries_file=""
spec_entries_file=""
module_entries_file=""
trap 'rm -f "$doc_entries_file" "$spec_entries_file" "$module_entries_file"' EXIT
doc_entries_file="$(mktemp /tmp/audit_docs.XXXXXX)"
spec_entries_file="$(mktemp /tmp/audit_specs.XXXXXX)"
for f in "${doc_files[@]}"; do
  audit_doc_file "$f" >> "$doc_entries_file"
done
docs_json="$(jq -s '.' "$doc_entries_file")"
[[ -z "$docs_json" || "$docs_json" == "null" ]] && docs_json="[]"

# Collect spec files
if [[ -d "$SPECS_DIR" ]]; then
  while IFS= read -r f; do
    audit_spec_file "$f" >> "$spec_entries_file"
  # POSIX-compatible alternative to -maxdepth 1 (works on macOS BSD find)
  done < <(find "$SPECS_DIR" -name "*.md" -type f -not -path "$SPECS_DIR"/*/* 2>/dev/null | sort)
fi
specs_json="$(jq -s '.' "$spec_entries_file")"
[[ -z "$specs_json" || "$specs_json" == "null" ]] && specs_json="[]"

# Find untracked files (in docs/ but not in index)
untracked_json="[]"
if [[ -n "$INDEX_CONTENT" ]]; then
  untracked_json="$(echo "$docs_json" | jq '[.[] | select(.in_index == false) | .path]')"
fi

# Summary statistics
summary_json="$(echo "$docs_json" "$specs_json" | jq -s '
  {
    total_docs: (.[0] | length),
    high_risk: ([.[0][] | select(.risk_level == "high")] | length),
    medium_risk: ([.[0][] | select(.risk_level == "medium")] | length),
    low_risk: ([.[0][] | select(.risk_level == "low")] | length),
    total_specs: (.[1] | length),
    specs_built: ([.[1][] | select(.classification == "built_complete" or .classification == "built_partial")] | length),
    specs_abandoned: ([.[1][] | select(.classification == "never_built_old")] | length),
    specs_recent: ([.[1][] | select(.classification == "never_built_recent")] | length)
  }
')"

# ================================================================
# AUDIT MODULE DOCS (if docs/modules/ exists)
# ================================================================

module_docs_json="[]"
MODULES_DIR="docs/modules"
if [[ -d "$MODULES_DIR" ]]; then
  module_entries_file="$(mktemp /tmp/audit_modules.XXXXXX)"

  while IFS= read -r f; do
    local_basename="$(basename "$f")"
    local_module_name="${local_basename%.md}"

    # Parse YAML frontmatter for last_analyzed commit and source_paths
    # Uses sed/grep only — no yq dependency
    local_frontmatter=""
    if head -1 "$f" | grep -q "^---"; then
      local_frontmatter="$(sed -n '2,/^---$/p' "$f" | sed '$d' | tr -d '\r')"
    fi

    # Extract last_analyzed commit from frontmatter
    local_last_commit=""
    if [[ -n "$local_frontmatter" ]]; then
      local_last_commit="$(echo "$local_frontmatter" | grep -E '^\s+commit:' | head -1 | sed 's/.*commit:\s*//' | tr -d '"' | tr -d "'" | tr -d ' ')"
    fi

    # Extract source_paths from frontmatter (lines starting with "  - " after "source_paths:")
    local_source_paths=()
    if [[ -n "$local_frontmatter" ]]; then
      local_in_source_paths=false
      while IFS= read -r line; do
        if [[ "$line" =~ ^source_paths: ]]; then
          local_in_source_paths=true
          continue
        fi
        if [[ "$local_in_source_paths" == true ]]; then
          if [[ "$line" =~ ^[[:space:]]+-[[:space:]] ]]; then
            local_path="$(echo "$line" | sed 's/^[[:space:]]*-[[:space:]]*//')"
            local_source_paths+=("$local_path")
          else
            local_in_source_paths=false
          fi
        fi
      done <<< "$local_frontmatter"
    fi

    # Count unique commits touching any source_path since last_analyzed commit
    local_commits_since=0
    local_staleness="fresh"
    if [[ -n "$local_last_commit" ]] && git rev-parse "$local_last_commit" > /dev/null 2>&1; then
      if (( ${#local_source_paths[@]} > 0 )); then
        local_commits_since="$(git log --format="%H" "$local_last_commit"..HEAD -- "${local_source_paths[@]}" 2>/dev/null | sort -u | wc -l | tr -d ' ')"
      fi

      if (( local_commits_since == 0 )); then
        local_staleness="fresh"
      elif (( local_commits_since <= 5 )); then
        local_staleness="minor_drift"
      elif (( local_commits_since <= 20 )); then
        local_staleness="moderate_drift"
      else
        local_staleness="major_drift"
      fi
    fi

    # Extract confidence from frontmatter
    local_confidence="unknown"
    if [[ -n "$local_frontmatter" ]]; then
      local_confidence="$(echo "$local_frontmatter" | grep -E '^confidence:' | head -1 | sed 's/confidence:\s*//' | tr -d ' ')"
      [[ -z "$local_confidence" ]] && local_confidence="unknown"
    fi

    # Extract generated_by from frontmatter
    local_generated_by="unknown"
    if [[ -n "$local_frontmatter" ]]; then
      local_generated_by="$(echo "$local_frontmatter" | grep -E '^generated_by:' | head -1 | sed 's/generated_by:\s*//' | tr -d ' ')"
      [[ -z "$local_generated_by" ]] && local_generated_by="unknown"
    fi

    jq -n \
      --arg path "$f" \
      --arg module "$local_module_name" \
      --arg last_commit "${local_last_commit:-null}" \
      --argjson commits_since "$local_commits_since" \
      --arg staleness "$local_staleness" \
      --arg confidence "$local_confidence" \
      --arg generated_by "$local_generated_by" \
      --argjson source_path_count "${#local_source_paths[@]}" \
      '{
        path: $path,
        module: $module,
        last_analyzed_commit: (if $last_commit == "null" then null else $last_commit end),
        commits_since_analyzed: $commits_since,
        staleness: $staleness,
        confidence: $confidence,
        generated_by: $generated_by,
        source_path_count: $source_path_count
      }' >> "$module_entries_file"
  done < <(find "$MODULES_DIR" -name "*.md" -type f 2>/dev/null | sort)

  module_docs_json="$(jq -s '.' "$module_entries_file")"
  [[ -z "$module_docs_json" || "$module_docs_json" == "null" ]] && module_docs_json="[]"
fi

# Assemble final output
jq -n \
  --arg generated_at "$GENERATED_AT" \
  --arg docs_dir "$DOCS_DIR" \
  --arg specs_dir "$SPECS_DIR" \
  --arg index_file "$INDEX_FILE" \
  --argjson days_high "$DAYS_HIGH" \
  --argjson days_medium "$DAYS_MEDIUM" \
  --argjson specs_max_age "$SPECS_MAX_AGE" \
  --argjson docs "$docs_json" \
  --argjson specs "$specs_json" \
  --argjson untracked "$untracked_json" \
  --argjson summary "$summary_json" \
  --argjson module_docs "$module_docs_json" \
  '{
    generated_at: $generated_at,
    params: {
      docs_dir: $docs_dir,
      specs_dir: $specs_dir,
      index_file: $index_file,
      days_high: $days_high,
      days_medium: $days_medium,
      specs_max_age: $specs_max_age
    },
    docs: $docs,
    specs: $specs,
    untracked: $untracked,
    module_docs: $module_docs,
    summary: $summary
  }'
```

```bash

bash {{discovery.agent_dir}}/hooks/audit-docs.sh \
  --docs-dir documentation \
  --specs-dir plans \

  --days-medium 30

bash {{discovery.agent_dir}}/hooks/audit-docs.sh | jq '.summary'
```

### JSON Output Schema

The script outputs a single JSON object with these fields:

| Field | Type | Description |
|-------|------|-------------|
| `generated_at` | string | ISO-8601 timestamp |
| `params` | object | The parameters the script was invoked with |
| `docs` | array | One entry per doc file — see fields below |
| `specs` | array | One entry per spec file — see fields below |
| `untracked` | array | Paths of docs not listed in the index file |
| `module_docs` | array | One entry per module doc — see fields below (empty if `docs/modules/` doesn't exist) |
| `summary` | object | Aggregate counts |

**Doc entry fields:** `path`, `last_edit_days`, `last_edit_date`, `commits_90d`, `is_temporary`, `temp_pattern_matched`, `in_index`, `co_change_files` (array of `{path, commits_since_doc_edit}`), `todo_count`, `has_stale_versions`, `risk_level` (`"high"` | `"medium"` | `"low"`).

**Spec entry fields:** `path`, `age_days`, `git_evidence_commits`, `listed_files_exist`, `classification` (`"built_complete"` | `"built_partial"` | `"never_built_old"` | `"never_built_recent"`).

**Module doc entry fields:** `path`, `module`, `last_analyzed_commit`, `commits_since_analyzed`, `staleness` (`"fresh"` | `"minor_drift"` | `"moderate_drift"` | `"major_drift"`), `confidence`, `generated_by`, `source_path_count`. Staleness levels: fresh (0 commits to source_paths since last_analyzed), minor drift (1-5), moderate drift (6-20), major drift (20+). Confidence decay: high confidence + moderate/major drift → effective medium confidence.

## Hook Wiring Reference (Claude Code)

Hooks are wired in the builder agent's frontmatter (created in Step 4). The pattern:

```yaml
hooks:
  PostToolUse:
    - matcher: "Write|Edit"
      hooks:
{{#each discovery.linters}}
        - type: command
          command: bash $PROJECT_DIR/{{discovery.agent_dir}}/hooks/validators/{{name}}_validator.sh
{{/each}}
{{#each discovery.type_checkers}}
        - type: command
          command: bash $PROJECT_DIR/{{discovery.agent_dir}}/hooks/validators/{{name}}_validator.sh
{{/each}}
    - matcher: "Bash"
      hooks:
        - type: command
          command: bash $PROJECT_DIR/{{discovery.agent_dir}}/hooks/audit-docs-hook.sh
```

The `check-env.sh` is wired as a session-start or PreToolUse hook (platform-dependent).

> **Session-start hook wiring (Claude Code):** Wire `check-env.sh` as a PreToolUse hook in the project's `.claude/settings.local.json` or as a manual first-run check. Claude Code does not yet have a native session-start hook mechanism, so use one of:
> - Add to builder frontmatter as a PreToolUse matcher (if supported by the platform version)
> - Document it as a manual first step in the builder instructions
> - Wire it in `.claude/settings.local.json` under `hooks.PreToolUse`

> **Monorepo note:** Workspace scoping (matching `$file_path` against workspace paths to determine the correct working directory) is handled internally by each validator script. The hook wiring in the builder frontmatter is identical for monorepo and non-monorepo projects — no per-workspace hook entries are needed.

## OpenCode Adaptation

OpenCode does not support YAML frontmatter-based hooks in agent definitions. Instead, hooks are **TypeScript/JavaScript plugins** that subscribe to events.

### Hook Events

| Claude Code | OpenCode Event | Description |
|-------------|---------------|-------------|
| `PostToolUse` matcher `"Write\|Edit"` | `tool.execute.after` | Fires after a tool completes |
| `PostToolUse` matcher `"Bash"` | `tool.execute.after` | Same event, filter on tool name |
| Session-start / `PreToolUse` | `tool.execute.before` | Fires before a tool executes |

### Strategy: Thin TypeScript Wrapper Around Bash Scripts

The validation logic stays in the same bash scripts used by Claude Code. The TypeScript plugin is a thin wrapper (~15 lines) that:
1. Filters events by tool name
2. Shells out to the bash validator
3. Throws on non-zero exit to block the operation

This means validation logic lives in one place regardless of platform.

### TypeScript Plugin Template

Create this file at `{{discovery.agent_dir}}/hooks/validate-on-write.ts`:

```typescript
// validate-on-write.ts — PostToolUse validator for OpenCode
// Shells out to the same bash validators used by Claude Code
import { execSync } from "child_process";
import { resolve } from "path";

const HOOKS_DIR = resolve(__dirname, "validators");

// List your validators here — one per linter/type-checker
const VALIDATORS = [
{{#each discovery.linters}}
  "{{name}}_validator.sh",
{{/each}}
{{#each discovery.type_checkers}}
  "{{name}}_validator.sh",
{{/each}}
];

export default {
  event: "tool.execute.after",
  filter: (event: any) => ["write", "edit"].includes(event.tool),
  handler: async (event: any) => {
    const input = JSON.stringify({ tool_input: event.args });
    for (const validator of VALIDATORS) {
      let output = "";
      try {
        output = execSync(`bash "${HOOKS_DIR}/${validator}"`, {
          input,
          encoding: "utf-8",
          timeout: 120_000,
        });
      } catch (err: any) {
        output = err.stdout || "";
      }
      // Parse JSON output — validators always exit 0, communicating via stdout
      try {
        const result = JSON.parse(output || "{}");
        if (result.decision === "block") {
          throw new Error(result.reason);
        }
      } catch (parseErr) {
        if (parseErr instanceof Error && parseErr.message && output.includes('"block"')) {
          throw parseErr; // Re-throw if this was our block error
        }
        // Non-JSON output — allow
      }
    }
  },
};
```

Create a second plugin for the audit-docs hook at `{{discovery.agent_dir}}/hooks/audit-docs-plugin.ts`:

```typescript
// audit-docs-plugin.ts — Post-commit doc staleness warning for OpenCode
import { execSync } from "child_process";
import { resolve } from "path";

const HOOK_SCRIPT = resolve(__dirname, "audit-docs-hook.sh");

export default {
  event: "tool.execute.after",
  filter: (event: any) => event.tool === "bash" && (event.args?.command || "").includes("git commit"),
  handler: async (event: any) => {
    const input = JSON.stringify({ tool_input: event.args });
    const output = execSync(`bash "${HOOK_SCRIPT}"`, {
      input,
      encoding: "utf-8",
      timeout: 10_000,
    });
    const result = JSON.parse(output || "{}");
    if (result.reason) {
      console.warn(result.reason);
    }
  },
};
```

### OpenCode Validator Hook Wiring

No frontmatter changes needed — plugins are auto-discovered from the hooks directory. Ensure `{{discovery.agent_dir}}/hooks/` contains both `.sh` scripts and `.ts` plugin wrappers.
